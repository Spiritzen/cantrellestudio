1. CONTEXTE VISUEL À COMPRENDRE
==================================================

Sur la landing page, les lignes ne sont pas seulement un décor du Hero.

Elles restent perceptibles lorsque l’on descend dans la page :
- derrière le Hero ;
- derrière la section Approche ;
- plus bas au fil du scroll ;
- elles participent à la profondeur globale de la page.

C’est CE comportement que nous voulons comprendre.

Sur `/applications-metier-saas/`, à terme, nous voulons pouvoir retrouver le même principe :
- dans le Hero ;
- dans Méthode ;
- dans Cadrage ;
- derrière le CTA final « Un projet d'application métier ? » ;
- et potentiellement sur les autres pages Services.

Nous ne voulons donc pas un composant limité à un Hero de 500px de haut.
Nous voulons comprendre la vraie architecture de la landing avant de décider comment la reproduire.

11. RECOMMANDATION DE FUTURE ARCHITECTURE
==================================================

À partir de l’audit,
proposer UNE architecture recommandée pour la V2.

Le futur système doit idéalement permettre :

- une instance persistante de filaments sur une page ;
- visible derrière plusieurs sections ;
- variations de visibilité / position possibles selon le scroll ;
- aucun reset brutal entre sections ;
- aucune sortie définitive du viewport ;
- même fluidité que la Home ;
- préférence horizontale ;
- z-index bas ;
- contenus toujours lisibles ;
- possibilité de réutilisation sur :
  - Applications métier & SaaS
  - Sites professionnels
  - Développement sur mesure
  - éventuellement pages Studio

Donner un nom de composant suggéré, par exemple :
`PageFilaments.tsx`
ou meilleur nom si pertinent.
