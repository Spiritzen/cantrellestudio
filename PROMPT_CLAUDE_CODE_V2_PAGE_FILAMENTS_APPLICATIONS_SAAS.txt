==================================================
2. ARCHITECTURE DU CANVAS
==================================================

Reprendre le principe structurel validé de la Home :

- wrapper fixed plein viewport
- `position: fixed`
- `inset: 0`
- `pointer-events: none`
- z-index structurel bas
- Canvas transparent
- monté UNE SEULE FOIS pour la page
- jamais recréé par section

Le Canvas doit être indépendant du Hero :
même s’il est monté depuis la page Applications, sa surface doit couvrir le viewport entier.

IMPORTANT :
ne PAS créer un conteneur `overflow:hidden` limité au Hero.

C’est précisément l’erreur structurelle identifiée dans l’audit.

==================================================
3. CAMERA — REPRENDRE LA HOME
==================================================

Utiliser les valeurs de la Home :

- PerspectiveCamera R3F
- `fov: 34`
- `position: [0, 0, 7]`
- `dpr={[1, 1.5]}`

Ne pas inventer une autre caméra.

Le Canvas doit rester responsive via R3F.

==================================================
4. GÉNÉRATION DES FILAMENTS — COPIE FIDÈLE DE LA LOGIQUE HOME
==================================================

Reprendre les constantes et formules de `HeroSpheres.tsx`.

Base attendue :

- 5 filaments
- `HORIZONTAL_BIAS_PROBABILITY = 0.75`
- 3 ou 4 points de contrôle
- `xStart = rand(-4.6, -3.3)`
- `xEnd = rand(3.3, 4.6)`
- `z = rand(-4.4, -2.6)`
- `yCenter = rand(-1.7, 1.7)`
- `verticalSpread` :
  - horizontal : rand(0.15, 0.55)
  - libre : rand(0.9, 2.0)
- jitter x/z ±0.3
- `THREE.CatmullRomCurve3`
- `.getPoints(48)`

Générer ces lignes UNE SEULE FOIS au montage avec `useMemo(..., [])`.

NE PAS recalculer les points à chaque frame.

==================================================
5. RENDU DES LIGNES
==================================================

Utiliser `<Line>` de `@react-three/drei`.

Valeurs Home :

- couleur paire : `#F1EFE8`
- couleur impaire : `#E45F36`
- opacité paire : `0.12`
- opacité impaire : `0.09`
- `lineWidth={1}`
- `transparent`
- `depthWrite={false}`

Ne pas augmenter artificiellement leur visibilité.

La sensation doit rester :
- discrète
- premium
- organique
- presque atmosphérique

==================================================
6. MOUVEMENT — POINT CRITIQUE
==================================================

Le mouvement doit être celui de la Home :

UN SEUL groupe parent :
`filamentsRigRef`

Les 5 lignes restent statiques à l’intérieur de ce groupe.

À chaque frame :
faire tourner le GROUPE ENTIER autour de son axe Y LOCAL.

Base :
`rotation.y += delta * (0.012 + energy * 0.01)`

IMPORTANT :
- pivot = centre local du groupe
- PAS de `transform-origin` CSS
- PAS de pivot externe
- PAS de translation simulée
- PAS de boucle CSS 0→360
- PAS de reset
- PAS de mouvement indépendant par ligne

La rotation est cumulative, monotone, continue.

C’est la condition principale pour ne plus voir les traits s’échapper vers la droite.

==================================================
7. ÉNERGIE DE SCROLL
==================================================

Pour rester fidèle à la Home, reprendre proprement le principe d’énergie de scroll utilisé dans `HeroSpheres.tsx` :

- calcul de vitesse de scroll
- attaque rapide
- relâchement lent
- énergie clampée
- petite accélération de la rotation pendant le scroll

Réutiliser les constantes réelles de la Home si elles sont encore identiques au rapport.

Ne pas dupliquer une version approximative.

Si une extraction locale propre de quelques constantes / fonctions aide,
elle doit rester MINIMALE.

NE PAS modifier `HeroSpheres.tsx`.

==================================================
8. POSITION DES FILAMENTS SUR PAGE SERVICE
==================================================

Différence volontaire par rapport à la Home :

Sur la Home, les filaments accompagnent aussi la transition droite → centre du Hero.

Pour cette première version Page Services :
- NE PAS reproduire la migration droite→centre ;
- garder le rig de filaments centré dans le viewport dès le départ ;
- pas de targetX dépendant de la hauteur du Hero ;
- pas de targetZ ;
- pas de scale lié au scroll.

Pourquoi :
le besoin Service est un FOND DE PAGE persistant,
pas une scène Hero avec sphères à déplacer.

Le mouvement doit donc être encore plus simple :
- rig centré
- rotation Y continue
- petite accélération liée au scroll

==================================================
9. REDUCED MOTION
==================================================

Reprendre le pattern de la Home :

- `window.matchMedia("(prefers-reduced-motion: reduce)")`
- écoute des changements
- sous reduced-motion :
  - pas de rotation continue
  - scène statique
  - pas de boucle rAF inutile

Utiliser :
`frameloop="demand"`

quand reduced-motion est actif.

Ne jamais désactiver l’affichage du décor si cela crée un trou visuel :
les lignes peuvent rester visibles statiquement.
